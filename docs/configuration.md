# Installation and configuration

Switchboard runs on macOS and Linux. The interactive setup can create and
update the user configuration, so editing TOML is optional.

## Install

The release installer verifies checksums and writes `sb` to `~/.local/bin`:

```sh
curl -fsSL https://raw.githubusercontent.com/switchboard-code/switchboard/main/install.sh | bash
```

To build from source, install Go 1.26 and run:

```sh
go build -o sb ./cmd/sb
```

Shell completion is generated by the binary:

```sh
sb completion zsh
sb completion bash
sb completion fish
```

Each generated script includes its shell-specific install command in the
header. Completion entries are tested against the real command dispatcher.

## Updates

The TUI checks for releases at startup. By default it installs a verified
update in the background, leaving the current process untouched. The next run
uses the new binary. Switchboard detects package-manager installations and does
not replace them.

Use `sb update` for the same operation in a script. `/update channel beta`
follows prereleases. `/update auto off` keeps the release notice but disables
automatic installation.

## First-run setup

Run `sb` from a project directory. If no configuration exists, Switchboard
opens a setup checklist and probes each available provider. The Ollama row also
shows how many models are installed locally.

Providers that require a key use a masked prompt and store the value in the OS
credential service. If Codex CLI is signed in, setup can configure its token
helper for OpenAI. Choose the first tier's model to finish setup.

These commands remain available later:

| Command | Purpose |
| --- | --- |
| `/setup` | Reopen the setup checklist |
| `/models` | Browse models and bind tiers |
| `/login` and `/logout` | Manage provider credentials |
| `/doctor` or `sb doctor` | Probe providers, credentials, sandbox support, conditional tools, and MCP servers |

`doctor` uses the same provider probes as session startup. A failed row includes
the next action when one is known. On Linux, sandbox support requires a
canonical root-owned `bwrap` whose parent directories are also root-owned. The
binary and chain must have no group/other write bits and must not be writable
by the invoking user through effective permissions such as ACLs. A user-owned
or user-writable resolved binary is reported as unavailable; install bubblewrap
through a trusted system package.

## Config file

The user configuration is `~/.switchboard/config.toml`. Switchboard writes a
header into files it manages, but hand editing remains supported.

A ladder is an ordered set of tiers:

```toml
[tiers.t1]
label = "light"
model = "ollama/qwen3.5:9b-mlx"

[tiers.t2]
label = "deep"
model = "ollama/qwen3.8:27b-mlx"
effort = "high"

[tiers.t3]
label = "kimi"
model = "kimi/kimi-for-coding-highspeed"
fallback = ["ollama/qwen3.8:27b-mlx"]

[tiers.t4]
label = "codex"
model = "openai/gpt-5.6-sol"
surface = "subscription"
```

The `model` value identifies a provider and model. A tier may also set a
reasoning `effort`, serving `surface`, and ordered `fallback` targets. See
[Routing and the model ladder](routing.md) for selection and fallback rules.

## Profiles

A profile replaces the ladder for one workload while keeping provider slots,
credentials, and global settings:

```toml
[profiles.review.tiers.t1]
label = "review"
model = "openai/gpt-5.6-sol"
```

Start it with `sb -profile review`. `/tiers` reports the active profile. Tier
changes made through `/models` are saved to that profile, while global settings
such as theme and budget remain global.

## Slots and persistent settings

Optional model roles are configured under `[slots]`. For example:

```toml
[slots]
advisor = "t2"
summarizer = "t3"
approver = "t1"
```

The advisor watches for stuck-agent signals. The summarizer handles manual and
automatic compaction regardless of the active tier. In `auto` permission mode,
`approver` selects the tier or direct target that reviews eligible commands.
Without the slot, Switchboard tries the ladder from its lowest tier. The
reviewer receives a bounded command-policy packet and can allow, deny, or
escalate. Errors or invalid results go to the user, or deny the command when no
listener exists. Reviewer calls are budgeted and recorded as approval work.
Shell or inline-interpreter code, sensitive commands, and ordinary commands
under macOS shared host-loopback confinement skip model review and ask the
user. Windows command execution also stays human-gated because descendant
cleanup is not guaranteed.

`/theme`, `/update`, `/compact`, and `/budget` update persistent settings.
`/think` changes reasoning effort for the running process; use `/models` to
persist a tier binding. `/theme` accepts `dark`, `light`, or `auto`.

## Sandbox selection

Command confinement defaults to off. Set a startup default in the user config:

```toml
[execution]
sandbox = "auto" # off, on, or auto; true and false are also accepted
```

`sb -sandbox` overrides the config with `on` for one process and requires
verified Seatbelt confinement on macOS or trusted system bubblewrap confinement
on Linux. Startup exits with an error when the requested profile is
unavailable.
`-sandbox=off|on|auto` provides an explicit process override.
`-mode yolo` requires the requested sandbox setting to be `off`; when the
config selects `on` or `auto`, pass `-sandbox=off` or change the config.

Inside a session, `/sandbox on`, `off`, or `auto` changes the process posture
immediately; `/sandbox status` reports it. `auto` uses verified confinement when
available and otherwise remains visibly off. The selection is independent of
permission mode. A successful change is saved as the next launch default. If
the save fails, the running process keeps the new posture and reports the
failure. See
[Security](security.md#permission-modes) for `auto`, `yolo`, and `bypass` mode
semantics.

## Targets and provider gateways

Routing operates on targets, not model names. A target includes the provider,
serving surface, model, price, cache behavior, and observed capabilities. The
same model reached through Ollama and through an OpenAI-compatible gateway is
therefore two targets.

Set `[providers.<name>] base_url` to redirect a provider adapter to a gateway.
This changes the address only. It does not merge prices, cache records, or
capability evidence with another target.

Credential sources and outbound secret checks are documented in
[Security](security.md).
